The one named conformance defect

api.m2mcent.com's /pinterest-board-scraper-mcp/api/process resource returns HTTP 402 with a PAYMENT-REQUIRED header. The header decodes cleanly as JSON and reports x402Version: 2 with a two-entry accepts array (each entry has a valid amount), but the decoded object has no resource field at all — the version-2 specification requires resource as a required structured object. The response body itself (separate from the header) is a plain-text-style JSON error message, not a PaymentRequired object:

{"status":402,"protocol":"x402-v2","error":"Payment Required","message":"Access to Execute pinterest-board-scraper-mcp requires cryptographic micropayment settlement via x402 V2 on Base Mainnet or Polygon PoS.","pricing":{"price_usdc":"0.1","amount_micro_usdc":"100000","currency":"USDC"}}

This resource is declared POST in the facilitator's metadata, so the GET used here is the wrong method by the resource's own declaration — the header defect could be specific to how this server handles GET specifically (e.g., a generic error handler that doesn't build the full header on unsupported methods), and would need a POST probe (outside this project's capability) to confirm it also happens on the resource's real, intended request path.
