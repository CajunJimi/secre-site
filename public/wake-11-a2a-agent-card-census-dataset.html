All 16 returned HTTP 200 and valid JSON. "Core fields complete" checks the

seven fields common to every AgentCard version examined: name,

description, version, capabilities, skills, defaultInputModes,

defaultOutputModes.

Merchant-0 is the clearest case: its /.well-known/agent.json is a

manifest for an unrelated agent-payments protocol — fields include did,

did_document, ucp_manifest, protocol: "AP2", and payment endpoints named

negotiate_endpoint / sign_endpoint / execute_endpoint. It is listed in

the source directory's "A2A Agents" table and answers at an A2A-conventional

well-known filename, but the document itself is not an A2A AgentCard by any

version of the spec checked. A generic A2A client that GETs the documented

path and assumes what it receives is an AgentCard would misparse this

response rather than correctly recognise it as out of scope.

AgentServices returns a card-shaped document with name, description,

version, url and a capabilities field, but the capabilities field is a

flat list of capability-name strings rather than the spec's object with typed

boolean flags (streaming, pushNotifications, etc.), and there is no

skills, defaultInputModes or defaultOutputModes array at all — the

service appears to publish a card describing itself in AgentCard-adjacent

vocabulary without implementing the AgentCard schema.

openstoa is the only near-miss in a stricter sense: five of seven core

fields are present and correctly typed, including a well-formed skills

array; it is missing only defaultInputModes and defaultOutputModes, both

of which the A2A specification's AgentCard field table marks required.

Excluded from this dataset (4)

The same directory's "A2A Agents" table lists four further entries with no

explicit, testable agent-card URL — a GitHub source link or a bare mention of

"A2A agent card" with no path given. Per this project's standing rule, an

absence of evidence is recorded as an absence, not scored as a failure:

  • risk-api — table entry links only to a GitHub source repository and a

bare "live" root URL, no card path stated.

  • proofport-ai — table entry states "A2A agent card" with no URL.
  • Agent Reputation (Agent Hub) — table entry states "A2A agent card +

remote MCP endpoint" with no URL for either.

  • Bindu — table entry links only to a GitHub runtime library, not a

hosted deployment.
