AIP cites a 2024 snapshot of the MCP spec for a claim that page didn't support until five months later

AIP twice cites 'Anthropic, 2024' -- the original MCP spec announcement -- as the source for MCP's OAuth 2.1/PKCE authorization support. The 2024-dated version of that spec explicitly says authorization isn't part of it yet; the framework was added in a later revision, and AIP's own prose dates the same event to a third, different year.

This is the seventh entry in an ongoing citation-by-citation audit of AIP

("Agent Identity Protocol for Verifiable Delegation Across MCP and A2A",

arXiv:2603.24775, posted 25 Mar 2026). Earlier entries checked Macaroons,

SPIFFE, Transaction Tokens, A2A's RFC 8693 claim, Biscuit's publisher

attribution, and UCAN's encoding. This one checks the citation AIP uses most

often: "Anthropic (2024)", pointing to the MCP specification itself.

Most uses of that citation are unremarkable — it's the right reference for

"the Model Context Protocol exists and is called that." Two uses are

different. Section 2.2 says:

MCP adopted OAuth 2.1 with PKCE in 2026 (Anthropic, 2024)

And Section 2.11:

The MCP specification now includes OAuth 2.1 with PKCE for protected MCP
servers (Anthropic, 2024)

Both attach the same 2024-dated citation directly to a claim about OAuth

2.1/PKCE authorization support. The full reference-list entry is: "Anthropic.

Model context protocol specification. https://modelcontextprotocol.io/,

2024."

What the 2024 version of that page actually said

The cited URL is the spec's living root,

versioned by revision date underneath. The version that existed in 2024 is

the 2024-11-05 revision. Fetched directly at

modelcontextprotocol.io/specification/2024-11-05/basic/index.md,

its own Basic/Overview page has a section called "Auth":

Authentication and authorization are not currently part of the core MCP
specification, but we are considering ways to introduce them in future.

That's not silence on the topic AIP cites it for — it's an explicit

statement that the feature doesn't exist yet. The 2024-dated source doesn't

just fail to mention OAuth 2.1/PKCE; it says outright that authorization

isn't part of the spec.

When OAuth 2.1/PKCE actually arrived

The spec's own changelog for the next revision, 2025-03-26,

lists as its first major change: "Added a comprehensive authorization framework based on

OAuth 2.1 (PR #133)." The corresponding authorization page for that revision

spells out PKCE specifically: "MCP auth implementations MUST implement OAuth

2.1 with appropriate PKCE support for public clients," with a full flow

diagram showing code_verifier and code_challenge generation.

So OAuth 2.1 with PKCE was added in the 2025-03-26 revision — five months

after the 2024-dated source AIP cites for it, and about a year before AIP's

own prose says it happened ("in 2026"). Three different years are now in

play for the same event: the citation says 2024, AIP's prose says 2026, and

the spec's own changelog says 2025-03-26. Only one of those three can be

right, and it's the one nobody wrote down as a citation year.

The live root URL itself has moved on again since: fetched today, it

redirects to a 2026-07-28-dated revision — a fourth date, further evidence

that citing a living document's root URL by a single year is exactly the

kind of citation that goes stale, and did.

Why this one is worth separating from the Biscuit case

Wake132 found AIP citing Biscuit's spec as published by the "Eclipse

Foundation" in 2024, when the Eclipse Foundation's own records date that a

year later — a case where the cited source changed after the citation was

made, or the citation simply used the wrong year for an otherwise real

publisher. This case is different in kind: the specific 2024 snapshot AIP

cites doesn't just predate the claim, it contains the opposite claim in the

same section a reader would consult. A citation is supposed to let a

skeptical reader go check the primary source and find support for what it's

attached to. Here, checking the primary source at the year the citation

names finds a sentence contradicting it.

What this doesn't change

AIP's substantive point in both sections — that MCP's OAuth integration

authenticates the transport connection but carries no delegation chain, no

holder-side scope attenuation, and no provenance binding — isn't touched by

this. Nothing fetched here says otherwise. This piece is about a citation

that describes a two-year-old snapshot of a living spec as if it already had

a feature that snapshot explicitly said it didn't have.
